Complexity Analysis

Big-O 數學基礎 • 求和技巧 • 遞迴式 • Master Theorem • 攤還分析

為什麼要精確分析,而不是「感覺」

刷題最常見的判斷是 「這個解會不會超時 / 溢位」。複雜度分析就是把「感覺」變成「可計算」:給定 n 的上限,算出操作數的量級,對照機器每秒約 10^8 ~ 10^9 次操作,就能判斷會不會 TLE。

核心心法:複雜度 = 「當輸入 n 變大時,操作數如何成長」。我們只在意 成長的量級,不在意常數與低階項——因為當 n 夠大,最高階項會主導一切。

三個漸進符號 (Asymptotic Notation)

符號意義白話
O(f)上界 (upper bound)「最多」不超過 f 的量級 — 最常用
Ω(f)下界 (lower bound)「至少」有 f 的量級
Θ(f)緊界 (tight bound)上下界相同 — 「就是」f 的量級

Big-O 的正式定義

T(n) = O(f(n))  ⟺  存在常數 c > 0, n₀,使得對所有 n ≥ n₀,  T(n) ≤ c · f(n)

白話翻譯:從某個 n₀ 之後,T(n) 永遠被 c·f(n) 壓在下面。那個常數 c 讓我們忽略係數,n₀ 讓我們忽略小 n 的雜訊。

例:證明 3n² + 5n + 100 = O(n²)

要找 c、n₀ 使 3n² + 5n + 100 ≤ c·n²
當 n ≥ 1:5n ≤ 5n²,100 ≤ 100n²
所以 3n² + 5n + 100 ≤ 3n² + 5n² + 100n² = 108n²
取 c = 108, n₀ = 1 即成立 → 是 O(n²) ✓

實務上不用這樣證。只要記住規則:丟掉常數係數、只留最高階項。3n² + 5n + 100 → O(n²)。上面的正式證明是說明「為什麼可以這樣丟」。

丟棄規則 (Simplification Rules)

  • 丟常數係數: O(3n) = O(n),O(n/2) = O(n)
  • 只留最高階: O(n² + n) = O(n²)
  • 加法取大者:兩段接續執行 → O(f) + O(g) = O(max(f,g))
  • 乘法相乘:巢狀 → O(f) × O(g) = O(f·g)
  • log 的底數無關: log₂n、log₁₀n 只差常數倍 → 都寫 O(log n)

由慢到快(n 大時操作數由少到多)。背起來,判斷 TLE 全靠它。

為什麼 log n 出現得這麼頻繁

log n = 「n 能被 2 除幾次直到剩 1」。每次操作把問題規模減半,就是 O(log n):

n → n/2 → n/4 → ... → 1
除了 k 次後剩 1:n / 2ᵏ = 1 → 2ᵏ = n → k = log₂n

所以二分搜尋、平衡樹、堆的高度、快速冪都是 O(log n)——它們的共同點都是「每步砍半」。

求和技巧 — 迴圈複雜度的數學核心

分析迴圈,本質是把每層迴圈的執行次數加起來。掌握幾個常見級數和,就能秒算。

1. 等差級數 (Arithmetic Series)

1 + 2 + 3 + ... + n = n(n+1)/2 = Θ(n²)

推導(高斯配對法):

S = 1 + 2 + ... + (n-1) + n
S = n + (n-1) + ... + 2 + 1  (反過來寫)
兩式相加:2S = (n+1) + (n+1) + ... + (n+1) = n 個 (n+1)
2S = n(n+1) → S = n(n+1)/2

這就是為什麼「巢狀迴圈跑三角形」是 O(n²)。例如 LC 1359 Count Orders 的內層 Σj = (2i-1)(2i)/2 = i(2i-1),以及 LC 2563 Fair Pairs 的雙迴圈,底層都是這條等差和。

2. 平方和

1² + 2² + ... + n² = n(n+1)(2n+1)/6 = Θ(n³)

3. 等比級數 (Geometric Series)

1 + 2 + 4 + ... + 2ᵏ = 2^(k+1) − 1 = Θ(2ᵏ)

一般式:1 + r + r² + ... + rᵏ = (r^(k+1) − 1)/(r − 1)

關鍵洞見:等比級數的和 ≈ 最大那一項。 1+2+4+...+n = 2n−1 ≈ 2n = O(n)。所以「每次規模砍半的總工作量」是 O(n) 不是 O(n log n)——最後一層(最大)就佔了一半。這個 反直覺 的事實在 Master Theorem 和 build-heap 分析裡是關鍵。

4. 調和級數 (Harmonic Series)

1 + 1/2 + 1/3 + ... + 1/n = Θ(log n)

用途:埃拉托斯特尼篩法的複雜度 Σ n/i = n·(1+1/2+...+1/n) = n·Θ(log n) = Θ(n log n)(其實更精確是 O(n log log n))。

常見級數速查

Σ in(n+1)/2Θ(n²)
Σ i²n(n+1)(2n+1)/6Θ(n³)

迴圈分析 — 從程式碼到 Big-O

方法:從最內層往外,數每層跑幾次,相乘。變動邊界的用求和。

範例 1:固定巢狀 → 相乘

for (int i = 0; i < n; i++)       // n 次
    for (int j = 0; j < n; j++)   // n 次
        sum++;                    // O(1)
// 總計 n × n = O(n²)

範例 2:三角形巢狀 → 等差和

for (int i = 0; i < n; i++)       // i = 0..n-1
    for (int j = i; j < n; j++)   // 跑 (n-i) 次
        sum++;
總次數 = Σ(n−i) for i=0..n-1 = n + (n−1) + ... + 1
= n(n+1)/2 = Θ(n²)

常見誤判:看到「內層從 i 開始」以為是 O(n·something) 就慌。其實三角形巢狀還是 O(n²)——只是常數變 1/2,而常數要丟掉。

範例 3:規模砍半 → log

for (int i = n; i > 1; i = i / 2)   // 砍半直到 1
    sum++;
// n → n/2 → n/4 → ... → 1,共 log₂n 次 → O(log n)

範例 4:內層與外層變數綁定 → 相乘後求和

for (int i = 1; i < n; i *= 2)      // log n 次
    for (int j = 0; j < i; j++)      // i 次
        sum++;
i = 1, 2, 4, ..., n → 內層跑 1 + 2 + 4 + ... + n 次
= 等比級數 ≈ 2n = Θ(n)  (不是 O(n log n)!)

陷阱:外層 log n 次、內層最多 n 次,直覺以為 O(n log n)。但內層次數是 1,2,4,...,n 的等比級數,和 ≈ 最大項 = 2n = O(n)。等比級數「和 ≈ 最大項」的威力。

範例 5:兩段接續 → 取大者

sort(arr);                    // O(n log n)
for (int x : arr) process(x);   // O(n)
// O(n log n) + O(n) = O(n log n)  ← 取大者

while + 雙指針 → 攤還 O(n)

int j = 0;
for (int i = 0; i < n; i++) {
    while (j < n && cond) j++;   // j 只增不減
}
// 看似巢狀,但 j 全程最多走 n 步 → 總計 O(n),不是 O(n²)

常見模式:滑動窗口、LC 2434 robotWithString 的 stack、LC 2197 非互質合併——都是「看似巢狀,但內層指標全程只走 O(n) 步」→ 攤還 O(n)。判斷關鍵:內層變數會不會在外層迭代間「重置」?不重置 → 攤還。

遞迴式 (Recurrence Relations)

遞迴/分治演算法的複雜度,寫成遞迴式:T(n) 用更小的 T 表示。解它就得到複雜度。

遞迴式怎麼寫

一個分治演算法通常長這樣:

T(n) = a · T(n/b) + f(n)
  • a = 遞迴呼叫幾次(分成幾個子問題)
  • n/b = 每個子問題的規模(除以幾)
  • f(n) = 分割 + 合併的成本(非遞迴部分)

方法一:遞迴樹 (Recursion Tree)

把每層的工作量畫成樹,加總所有層。以 Merge Sort T(n) = 2T(n/2) + n 為例:

層 0:            n                    工作 = n
層 1:       n/2     n/2               工作 = n/2 + n/2 = n
層 2:    n/4 n/4   n/4 n/4            工作 = 4 × n/4 = n
  ...                                每層都是 n
層 k:   1  1  1  ...  1  (n 個葉)     工作 = n
每層工作量都是 n
層數 = 樹高 = log₂n(每層砍半)
總工作 = n × log₂n = Θ(n log n)

方法二:代入展開法 (Substitution)

以 T(n) = 2T(n/2) + n 反覆展開:

T(n) = 2T(n/2) + n
= 2[2T(n/4) + n/2] + n = 4T(n/4) + 2n
= 8T(n/8) + 3n
= 2ᵏT(n/2ᵏ) + k·n  (展開 k 次)
當 n/2ᵏ = 1 → k = log₂n,T(1)=1
= n·T(1) + n·log₂n = n + n log n = Θ(n log n)

常見遞迴式對照

遞迴式解典型演算法
T(n) = T(n/2) + O(1)O(log n)二分搜尋
T(n) = T(n−1) + O(1)O(n)線性遞迴
T(n) = 2T(n/2) + O(n)O(n log n)Merge Sort、快排(平均)
T(n) = 2T(n/2) + O(1)O(n)樹遍歷、build heap
T(n) = T(n−1) + O(n)O(n²)快排(最壞)、選擇排序
T(n) = 2T(n−1) + O(1)O(2ⁿ)河內塔、樸素費氏

注意 T(n/2) 和 T(n−1) 的天壤之別:T(n−1)+O(1) 是 O(n),但 T(n/2)+O(1) 是 O(log n)。前者每次減 1(線性次數),後者每次砍半(對數次數)。這也是為什麼「砍半」的演算法快得多。

Master Theorem — 分治遞迴式的速解公式

對形如 T(n) = a·T(n/b) + f(n) 的遞迴式,不用展開,直接套公式。這是分治複雜度的萬用鑰匙。

T(n) = a·T(n/b) + f(n),  a ≥ 1, b > 1

比較 f(n) 與 n^(log_b a)

關鍵是比較「合併成本 f(n)」和「葉子總數 n^(log_b a)」誰大。令 c* = log_b a:

情況條件結果誰主導
Case 1f(n) = O(n^(c*−ε))Θ(n^c*)葉子(遞迴)主導
Case 2f(n) = Θ(n^c*)Θ(n^c* · log n)兩者平衡
Case 3f(n) = Ω(n^(c*+ε))Θ(f(n))根(合併)主導

直覺: n^(log_b a) 是遞迴樹「葉子的總數」= 純遞迴的工作量。f(n) 是每層合併的工作量。誰成長得快,誰就決定總複雜度;一樣快就多一個 log n 因子(每層都貢獻同樣多,共 log 層)。

怎麼算 log_b a

log_b a = 「b 的幾次方等於 a」
log₂2 = 1 (2¹=2),   log₂4 = 2 (2²=4),   log₂8 = 3
log₃9 = 2 (3²=9),   log₄2 = 0.5 (4^0.5=2)

三個經典套用

Merge Sort: T(n) = 2T(n/2) + n

a=2, b=2, f(n)=n → c* = log₂2 = 1
f(n) = n = Θ(n¹) = Θ(n^c*) → Case 2
結果 = Θ(n · log n) ✓

二分搜尋: T(n) = T(n/2) + 1

a=1, b=2, f(n)=1 → c* = log₂1 = 0
f(n) = 1 = Θ(n⁰) = Θ(n^c*) → Case 2
結果 = Θ(n⁰ · log n) = Θ(log n) ✓

樸素矩陣相乘子問題: T(n) = 8T(n/2) + n²

a=8, b=2, f(n)=n² → c* = log₂8 = 3
f(n) = n² = O(n^(3−ε)) (ε=1) → Case 1(葉子主導)
結果 = Θ(n³) ✓ (這也是為什麼 Strassen 用 a=7 來壓成 n^2.81)

Master Theorem 的限制:只適用 a·T(n/b)+f(n) 這種「等分」遞迴。T(n)=T(n/3)+T(2n/3)+n(不等分)、T(n)=T(n−1)+n(減法型)不能套,要用遞迴樹或代入法。

攤還分析 (Amortized Analysis)

有些操作偶爾很貴,但多數很便宜。攤還分析算的是「一連串操作的平均成本」,而非單次最壞成本。

核心區別:攤還 ≠ 平均(average case)。平均是對「隨機輸入」取期望;攤還是對「一連串操作」保證總成本上界,不依賴機率——即使最壞輸入也成立。

經典例:動態陣列 (ArrayList) 的 push

陣列滿了要「擴容」= 開兩倍大的新陣列 + 複製全部元素(O(n))。單次 push 最壞 O(n),但攤還是 O(1)。

聚合法 (aggregate):算 n 次 push 的總成本

擴容發生在 size = 1, 2, 4, 8, ..., n
複製成本總和 = 1 + 2 + 4 + ... + n = 等比級數 ≈ 2n
n 次 push 總成本 = n(每次寫入) + 2n(複製) = 3n
平均每次 = 3n / n = O(1) 攤還 ✓

又是等比級數「和 ≈ 最大項」在起作用:所有擴容複製加起來只有 2n,不是 n × n。所以動態陣列的正常擴容其實很便宜;真正會爆記憶體的是「一開始就對每個節點預配大容量」的用法(見下方空間複雜度)。

三種攤還分析方法

方法做法
聚合法 (Aggregate)算 n 次操作總成本 T(n),攤還 = T(n)/n
記帳法 (Accounting)便宜操作「預存」代價,貴操作「提領」
位能法 (Potential)定義位能函數 Φ,攤還成本 = 實際 + ΔΦ

常見的攤還例子

  • 單調棧(robotWithString、非互質合併、min-product):每個元素最多入棧一次、出棧一次 → n 個元素總共 2n 次棧操作 → 攤還 O(n),即使某次 while 彈很多個。
  • 滑動窗口(longest nice subarray):左右指標各自單調前進,全程各走 n 步 → O(n)。
  • Union-Find 路徑壓縮:單次操作攤還 O(α(n))(反阿克曼函數,幾乎是常數)。

面試判斷法:看到「內層迴圈看似 O(n) 但變數只增不減、不重置」→ 用攤還論證「總步數 O(n)」,別報成 O(n²)。這個論證的理論名字就是 攤還分析。

實戰推算 — 用經典題練習

把前面的技巧套到幾道常見的 LeetCode 題目上。

1. Count Orders (LC 1359) — 打表 DP

for (int i = 2; i <= n; i++)
    for (int j = 1; j <= 2*i-1; j++)
        dp[i] += dp[i-1] * j;
內層次數 = Σ(2i−1) for i=2..n ≈ Σ 2i = 2·Σi = 2·n²/2 = n²
→ O(n²)。n≤500 → 250,000 次,遠低於 10⁸ → 穩過
(可優化:內層等差和有封閉解 i(2i−1) → O(n))

2. Echo Substring (LC 1316) — 暴力剪枝

枚舉半長 len × 起點 i × 比對 len 字元
= Σ_len Σ_i len ≈ n × n × n / 常數 = O(n³)
n≤2000 → 8×10⁹ 理論爆,但 while 很少跑滿 → 實測過
穩健版:lcp DP 或 rolling hash → O(n²) = 4×10⁶

3. Fair Distribution of Cookies (LC 2305) — 子集枚舉

枚舉子集的子集:Σ_{mask} 2^(popcount(mask))
= 每個 bit 三種狀態(不在/在大集/在小集)= 3ⁿ
n≤8 → 3⁸ = 6561 → 極快

「枚舉子集的子集 = 3ⁿ」的推導:對每個元素,它可以 (a) 不在 mask、(b) 在 mask 但不在子集、(c) 在子集。三選一,n 個獨立 → 3ⁿ。這是狀壓 DP 常見的複雜度。

4. 二分答案類 (LC 2861 合金) — n × 二分

每台機器二分答案:log(上界) 次
每次二分內檢查所有金屬:O(n)
k 台機器 → O(k · n · log(上界))
全 ≤ 10⁵ 級 → 約 10⁵ × 30 = 3×10⁶ → 穩過

5. Tarjan 找橋 (LC 1192) — 圖遍歷

DFS 每個節點訪問一次、每條邊看兩次(無向)
= O(V + E)
V,E ≤ 10⁵ → 2×10⁵ → 穩過

推算流程 SOP:(1) 找出主導的迴圈/遞迴結構 →(2) 用求和 / 遞迴式 / Master Theorem 算量級 →(3) 代入 n 上限算實際操作數 →(4) 對照 10⁸/秒 判斷 TLE →(5) 若超,想能不能降階(等差和封閉解、二分、單調棧、攤還)。

空間複雜度別忘了

  • 額外空間:不含輸入輸出,只算額外開的輔助結構。
  • DP 表 dp[n][m] → O(n·m);滾動陣列可壓到 O(m)(如 LC 1335 minDifficulty)。
  • 遞迴的隱藏空間:呼叫堆疊深度。DFS 鏈狀圖深度 O(n) 可能爆棧。
  • new ArrayList(n) × n 個 → O(n²) 空間 → MLE(常見陷阱:對每個節點都預配大容量)。
